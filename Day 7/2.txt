2. SOURCE-TO-TARGET MAPPING FOR FACT_SALES

Target: fact_sales, one row per order item.

stg_order_items.order_id              -> fact_sales.order_id          (natural key kept for trace)
stg_order_items.order_item_id         -> fact_sales.order_item_id     (part of the unique order item key)
stg_order_items.price                 -> fact_sales.price
stg_order_items.freight_value         -> fact_sales.freight_value
price + freight_value                 -> fact_sales.item_value        (derived)
constant 1                            -> fact_sales.item_count        (derived)
stg_orders.customer_id                -> dim_customer.customer_key    (lookup, not copied as text)
stg_order_items.product_id            -> dim_product.product_key      (lookup)
stg_order_items.seller_id             -> dim_seller.seller_key        (lookup)
stg_orders.order_purchase_timestamp   -> dim_date.date_key            (YYYYMMDD lookup)
first payment_type for the order      -> dim_payment_type.payment_type_key (lookup)
stg_orders.order_status               -> fact_sales.order_status

Surrogate sales_key is generated by MySQL. We also keep the natural pair
(order_id, order_item_id) as a unique key so a rerun cannot insert the same item twice.
