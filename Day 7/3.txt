3. SOURCE-TO-TARGET MAPPING FOR DIM_CUSTOMER

Source: olist_customers_dataset.csv

customer_id               -> dim_customer.customer_id        (natural key, kept)
customer_unique_id        -> dim_customer.customer_unique_id
customer_zip_code_prefix  -> dim_customer.zip_prefix
customer_city             -> dim_customer.city
customer_state            -> dim_customer.state

Generated by MySQL:
customer_key              -> surrogate primary key
effective_from            -> start date for this version (SCD type 2)
effective_to              -> end date for this version, NULL while current
is_current                -> 1 for the active row

dim_customer customer_id is not unique if we keep history, so the unique key is
(customer_id, effective_from). Lookups from fact_sales use customer_key.
